# SwarmCore AI 真人交互全功能测试计划

| 属性 | 值 |
|---|---|
| 状态 | EXECUTED_WITH_BLOCKERS |
| 版本 | 1.1 |
| 日期 | 2026-08-07 |
| 测试对象 | SwarmCore Web 控制台及其真实 REST、MCP、PostgreSQL、Temporal、Agent、Tool、Artifact 链路 |
| 执行方式 | AI 模拟真实用户操作 + Playwright 可重复回归 + 后端定向验证 |
| 结果事实源 | 本文件第 12 节记录本轮结果；长期实施状态仍以 `docs/swarmcore-development-plan.md` 为准 |

## 1. 目标

让 AI 在隔离测试项目中像真实用户一样使用产品，逐页进入、理解页面、填写表单、点击可用操作、等待异步结果、处理确认框和人工待办，并验证最终业务结果。

本轮目标：

1. 覆盖当前所有可达页面、可见功能和十项业务工作主链。
2. 覆盖成功、空数据、校验失败、服务失败、权限不足和异步等待等关键状态。
3. 对发现的可复现 Bug 完成“复现—定位—修复—补测试—浏览器复验—全量回归”闭环。
4. 将稳定场景沉淀为 Playwright，避免同类问题回归。
5. 形成可追溯证据，但不把 Mock、跳过或未执行项目记为通过。

本计划不以“页面能打开”代替功能通过，也不以 API 成功代替用户可完成业务。

## 2. 覆盖口径

“所有功能已测试”必须同时满足以下口径：

| 维度 | 覆盖要求 |
|---|---|
| 路由 | 每个当前路由至少从真实导航或业务入口到达一次；兼容重定向和 404 单独验证 |
| 控件 | 每个可见且启用的按钮、链接、输入、选择、菜单、分页、筛选和对话框操作至少被有效触发一次 |
| 禁用态 | 验证禁用原因可理解，且不能通过 URL、刷新或重复点击绕过 |
| 页面状态 | 按适用性覆盖加载、空、成功、校验错误、后端错误、无权限、长任务和刷新恢复 |
| 数据结果 | 页面反馈、REST 响应、数据库事实、Run/Task 状态、Artifact、Audit 和 Outbox 互相一致 |
| 多租户 | tenant/project 作用域不串数据；越权读取和写入 fail closed |
| 设备 | 全功能桌面覆盖；核心链路在平板、手机各复验；关键页面检查亮色和暗色 |
| 可用性 | 无页面崩溃、无意外横向滚动、无不可关闭遮罩、无重复提交、无无反馈点击 |
| 诊断 | 无未解释的浏览器 console error、请求失败、React 警告或服务端 5xx |

纯装饰元素、浏览器原生行为和明确标记为尚未实现的功能不计入“可操作控件”；但占位按钮、假成功提示、点击无效果都按 Bug 处理。

## 3. 执行原则

1. AI 按可见 UI 和业务文案决策，不直接调用隐藏接口跳过页面步骤。
2. 先做探索性真人操作，再把稳定复现路径写成 Playwright；两者都通过才关闭 Bug。
3. 测试运行在专用 tenant/project，禁止在共享或生产项目执行删除、取消、审批和外部副作用。
4. 删除、覆盖、取消、拒绝等破坏性动作只针对本轮新建数据，并先确认目标 ID 和影响范围。
5. 确定性基线使用 Fake Agent；真实模型、OCR、GitHub 和授权 Provider 在独立资格批次执行并明确证据级别。
6. 凭据只通过环境变量或 Vault 注入，不进入页面 URL、截图、Trace、日志或提交文件。
7. 一次只修复当前缺陷相关代码；行为变化必须新增或更新测试。
8. 每次修复后从原始用户入口重走，不只验证被修改的函数或接口。

## 4. 测试环境与前置门禁

### 4.1 环境

- Python 3.12、`uv` workspace、Node.js、pnpm 10.26。
- 独立 PostgreSQL 数据库、Temporal namespace、NATS stream 和本地对象存储前缀。
- 独立测试 tenant、project、用户身份和 maker/checker 身份。
- 桌面基准：Chromium 1440×900；平板：834×1112；手机：iPhone 13 viewport。
- 确定性批次设置 `SWARMCORE_USE_FAKE_AGENT=true`；真实 Provider 批次使用单独配置。

### 4.2 开始测试前必须通过

1. 记录 Git commit、工作树差异、数据库 migration head、服务版本和配置摘要。
2. 启动 API、Dispatcher、Control/Agent/Tool Worker、Artifact/Model Gateway、Event Publisher 和 Web。
3. 验证 `/health`、数据库、Temporal、Artifact、模型路由和测试文件可用。
4. 对测试项目执行受控 seed，记录所有测试对象 ID；不得复用来源不明的历史数据。
5. 执行一次现有 Playwright，建立“通过 / 产品 Bug / 测试过时 / 环境阻断”基线，不把历史失败直接忽略。
6. 检查浏览器时钟、时区、下载目录、弹窗和新标签页权限。

环境未就绪造成的失败标记为 `BLOCKED_ENV`，不进入产品修复，也不得写成通过。

## 7. Bug 闭环

### 7.1 严重级别

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 数据丢失/越权/Secret 泄露/不可逆错误副作用/系统整体不可用 | 立即停止相关测试，先隔离影响并修复 |
| P1 | 核心业务链阻断、稳定 5xx、状态错误、结果错误、无法恢复 | 当前批次内修复，修复前不得继续依赖链路 |
| P2 | 局部功能失效、错误反馈、重复提交、明显响应式或可访问性问题 | 本轮修复并回归 |
| P3 | 不阻断的文案、轻微视觉或低频体验问题 | 本轮修复；若明确接受遗留，必须记录原因和负责人 |

### 7.2 单个 Bug 的固定流程

1. 用用户语言记录入口、前置数据、操作、预期、实际结果和发生时间。
2. 保存截图、Playwright Trace、console、相关请求 ID、Run/Task/Assessment ID；日志仅保留最小必要片段。
3. 在干净会话中至少复现一次；并发或时序问题进行多次复现并记录概率。
4. 定位 UI、API、应用服务、领域、持久化、Temporal、Adapter 或环境根因。
5. 只做满足预期行为的最小修复；不顺手重构。
6. 先新增能在修复前失败的测试，再实施修复；无法自动化时说明原因并给出稳定人工复验脚本。
7. 执行变更文件静态检查、相关单元/集成/Vitest/Playwright。
8. 从最初页面入口重走完整路径，并检查数据库、Audit、Outbox、Artifact 和租户边界。
9. 重跑受影响批次；关闭时绑定 commit、测试结果和证据路径。

产品 Bug、测试脚本过时和环境问题必须分开记录，不能通过放宽断言、增加任意等待或跳过测试来“修复”。

## 8. 自动化沉淀规则

1. 每个主路由至少有一个 Playwright smoke；每条核心业务链至少有一个成功用例和一个失败/门禁用例。
2. 用户行为使用可访问角色和名称定位，优先 `getByRole`、`getByLabel`，不依赖脆弱 CSS 层级。
3. 等待业务状态或可见反馈，不使用无依据的固定 `sleep`。
4. API Mock 只用于确定性 UI 状态测试；真实链套件不得拦截核心业务 API。
5. 下载要校验文件名、非空、媒体类型，并按适用性校验 JSON Schema、PDF 文本或哈希。
6. 视觉截图只覆盖稳定布局；动态 ID、时间和流式状态先归一化。
7. 测试数据由 fixture/seed 创建并带唯一前缀，清理由同一测试上下文按显式 ID 完成。
8. 修复过的 Bug 必须保留回归用例，不用更新截图掩盖真实布局退化。

建议将新增套件按职责拆分为：

```text
apps/web/e2e/
  navigation-and-shell.spec.ts
  document-library.spec.ts
  execution-control.spec.ts
  capability-center.spec.ts
  strategy-management.spec.ts
  business-work-*.spec.ts
  tenancy-and-errors.spec.ts
```

## 9. 证据与报告

每次执行建立唯一 `testRunId`，本地证据建议写入 `output/ai-user-testing/<testRunId>/`，包含：

- `manifest.json`：commit、环境、浏览器、服务版本、测试数据 ID 和脱敏配置摘要；
- `coverage.json`：路由、控件、场景及 `PASS/FAIL/BLOCKED_ENV/NOT_APPLICABLE`；
- `bugs.json`：严重级别、复现步骤、根因、修复 commit、测试和状态；
- `screenshots/`、`traces/`：失败和关键完成状态的最小证据；
- `summary.md`：通过数、失败数、阻断项、未执行项和资格边界。

截图、Trace、日志和下载物是测试产物，默认不提交 Git。稳定结论、测试数量、未执行项和证据索引在完成后更新 `docs/swarmcore-development-plan.md`；只有同一不可变版本满足门禁时才能写 `VERIFIED`。

## 10. 完成标准

### 12.3 已修复缺陷

#### BUG-AIUT-001：可信完整性策略允许空输入，运行期才失败

- 严重级别：P1（核心运行链阻断）。
- 用户入口：`/runs/new`，选择 `trusted-contract-integrity-validate · 版本 1`。
- 实际结果：页面错误显示“无需额外输入”，允许创建；运行 `019fda4e-74f6-7c29-907b-5db7a2297585` 在 `classify` 任务失败，错误为 `ExpressionError: path 'input.payload.title' is not available`。
- 根因：`strategy-v1.json` 和当前 `strategy.json` 的运行表达式读取 `input.payload.title` 等字段，但 `inputSchema` 只有 `{ "type": "object" }`，前端和服务端都无法提前校验。
- 修复：为两个策略版本声明完整顶层输入属性、必填项以及 `payload.title`；保留共享策略需要的兼容字段，不修改已发布的不可变数据库版本。
- 回归：`tests/unit/test_contract_integrity_pack.py` 编译两个版本并断言运行模板所需输入契约；`new-run-page.test.tsx` 验证复杂策略使用 JSON 模式并阻断空对象创建。
- 数据迁移边界：当前数据库内已发布可信版本仍是旧契约。必须通过正常发布/seed 生成新不可变版本后，才能在真实页面对该修复做最终浏览器复验。
